## What "legitimate" means

Two independent floors, both of which must hold:

1. **Arm floor.** A round calls the event only if its amp/bamp segments cover
   at least `RB_MIN_ARM_FRAC = 0.15` of the target arm (2p = chr2 0-93.9 Mb,
   6p = chr6 0-59.8 Mb). Without this a few-Mb focal speck is indistinguishable
   from an arm-level gain.
2. **Majority floor.** The event is reported only if a *majority of the
   sample's available consensus rounds* call it. numbat's consensus iteration
   does not converge in this cohort, so any single round -- including numbat's
   own default `i = 2` -- is a stopping point, not an answer.

This is the rule from `src/select_round_by_majority.R`, and it is the same rule
that chose the round each `*_numbat.rds` was built from. `results/verify_majority_rds.csv`
confirms all 36 objects match their majority set, so the tables below and the
Seurat objects downstream cannot disagree.

### Support tiers

`strong` = max LLR >= 50 **and** cell fraction >= 0.5; `moderate` = one of the
two; `weak` = neither.

|  | 2p | 6p |
|---|---|---|
| strong | 8 | 14 |
| moderate | 4 | 1 |
| weak | 1 | 1 |

The tier boundary is not arbitrary. Across the 29 called rows the segment LLRs
fall into two groups with nothing between them -- 5.1-9.1 (n = 6) and >= 52
(n = 23). The per-cell posterior then splits that low-LLR group: four of the six
still carry the gain in 59-97% of cells, so a weak segment statistic on its own
is not disqualifying.

**Two calls fail both tests and should be treated as provisional:**

- `SRX14116946` **2p** -- a single whole-chromosome `bamp` segment (0.3-242.1 Mb,
  LLR 5.1) in 6.7% of cells. Whole-chr2 bamp at near-zero LLR is the signature of
  a baseline artefact, not a 2p gain; the arm floor passes only because the
  segment spans everything. Called in 3/4 rounds.
- `SRX11133588` **6p** -- 52.3 Mb at LLR 7.6 in 16.8% of cells, while the same
  sample's chr6q segments carry LLR 95 and 85. Called in 3/4 rounds.

## Drift from the pipeline's hardcoded list

`R/pipeline_targets_inputs.R:134-135` still routes the 2p/6p collages and
integrations off a hand-curated `rb_scna_samples` list that predates the revamp:

| | hardcoded | majority rule | added | dropped |
|---|---|---|---|---|
| 2p | 6 | 13 | 10 | 3 |
| 6p | 3 | 16 | 13 | 0 |

The three **dropped** from 2p are `SRX10264524`, `SRX10264525`, `SRX14116944` --
and the numbat support for 2p in these is absent, not merely weak:

| sample | 2p arm frac at selected round | rounds calling 2p |
|---|---|---|
| SRX10264524 | 0.000 | 1/4 |
| SRX10264525 | 0.000 | 0/4 |
| SRX14116944 | 0.072 | 0/4 |

`SRX10264525` and `SRX14116944` call 2p in **zero of four** rounds; two of the
three have no chr2 amp segment at all at their selected round. These same three
are exactly the hardcoded 6p list, which suggests the original 2p entry was
carried over from the 6p set or from external annotation rather than derived
from numbat.

Note this list drives real downstream artefacts -- `collages_2p`,
`corresponding_seus_2p`, and the `integrated_2p` Seurat objects. Reconciling it
is a separate decision, not made here.

## Reproducing

```bash
module purge && module load gcc/13.3.0 r/4.4.1
export LD_LIBRARY_PATH="$HOME/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
Rscript src/collate_2p_6p_gains.R
```

Outputs `results/rb_2p_6p_gain_by_sample.csv` (all 36 x 2 rows, called or not)
and `results/rb_2p_6p_gain_legitimate.csv` (the 29 called rows). Read-only with
respect to `output/numbat_sridhar/`.
