# How much does the answer depend on which numbat round you read?

**Cohort: `output/numbat_t1e5` (numbat `t = 1e-5`), the 24 P1-eligible tumors of
`docs/rb_scna_triage.md`.** Generated by `src/round_variation.R` from the flat
per-round TSVs; every number below is read from the CSVs it writes, so this
document cannot drift from them.

numbat runs its consensus loop `max_iter` times and writes a full artefact set per
round. The pipeline then keeps exactly one: the RDS is built with
`round_mode = "final"` — the highest round whose nine artefacts all exist — and
everything downstream reads only that. `results/numbat_active_round.csv` records the
result: round 4 for 32 samples, round 2 for the three held out.

**That round was chosen by rule and, for most samples, never inspected.** Only 7 of
35 were checked against their objects directly; the rest follow the rule. Since clone
numbering is round-specific, a wrong round silently invalidates every downstream
clone key — which has already happened once, to `SRX11133593`
(`docs/rb_scna_triage.md`, "A correction"). This document asks the obvious follow-up:
across the eligible cohort, how much would a different round have changed?

## What was measured

Per sample × round, from `segs_consensus_<k>.tsv` and `clone_post_<k>.tsv`:

| quantity | definition |
|---|---|
| **RB call set** | which of 1q+, 2p+, 6p+, 13q−, 16q− the consensus segmentation supports, via `numbat_rb_events()` |
| **arm coverage** | `numbat_rb_arm_frac()` — union extent of the supporting segments ÷ length of the target arm. An event counts only at ≥ `RB_MIN_ARM_FRAC` = **0.15** |
| **clone count** | distinct `clone_opt` in that round |
| **non-neutral segments** | distinct called segments |
| **breakpoint Jaccard** | agreement of the exact non-neutral breakpoint set between **consecutive** rounds; the table reports the **worst** step |

Only two samples have fewer than four rounds: `SRX11133592` and `SRX11133594` have
two, the rest have four. (`SRX11133593` has four complete rounds but its object
holds round 2 — see `docs/rb_scna_triage.md`.)

## Headline

**19 of 24 tumors call the same RB event set at every round.** Five do not, and in
four of those five round 1 is simply the immature one while the selected round sits
with the majority — benign. **One sample is the exception.**

Segmentation, by contrast, is never identical between rounds: **all 24** have a
worst-step breakpoint Jaccard below 0.9, 17 below 0.5, median **0.406**. **15 of 24**
change clone count across rounds.

The two findings pull in opposite directions and both matter:

- *Reassuring* — the **canonical arm-level calls** are mostly round-independent, so
  the cohort-level RB conclusions do not rest on the round choice.
- *Cautionary* — the **segmentation and the clone numbering** are not, so anything
  keyed by clone id is round-specific in practice, not just in principle.

## The one that matters: `SRX11133589`

It is the only sample where the **selected round disagrees with every other round**,
and it is not a rounding quibble:

| event | arm coverage, rounds 1 / 2 / 3 / 4 | called? |
|---|---|---|
| `1q_gain` | 0.447 / 0.629 / 0.698 / **0.128** | called / called / called / **--** |

Three rounds call 1q a whole-arm-scale gain at 45–70 % coverage. The selected round
collapses it to 12.8 %, dropping below the 0.15 floor, so `1q_gain` disappears from
that round's call set. Its other two events (`13q_loss` ≈ 0.97, `16q_loss` 0.16→0.28)
are stable. Clone count moves 5 → 8 → 8 → 7 and its breakpoint Jaccard is **0.158**,
the second worst in the cohort.

This deserves attention because `docs/rb_contrast_slides.tex` calls `SRX11133589`
**"the most useful tumor in the deck: both routes to both SCNAs"**, and lists 1q+
contrasts at clone 2→4 (tumor) and 1→4 (diploid). The round those contrasts are read
at is the one round where the consensus 1q signal is weakest.

**Stated precisely:** this is the *consensus segmentation* under a 0.15 arm-coverage
floor. The triage's contrast logic works from **per-clone genotypes**, a different
computation — so this does **not** by itself mean those triage rows are wrong. It
means this tumor's 1q call is the least robust to round choice in the cohort and is
the single best candidate for inspecting the rounds by eye, which
`results/iteration_summaries/SRX11133589_iterations.pdf` now supports directly.

## Clone numbering is the unstable part

`SRX22868103` ★ is the least stable sample in the cohort — worst Jaccard **0.150**,
clone count **14–18** (14, 17, 18, 17) and non-neutral segments 31–38 (31, 38, 34,
36) — yet its RB call set is identical at every round. It carries **three** contrasts in the deck, including the
cohort's only extension-based one (clone 2→3, 16q−).

That combination is the practical warning of this document: **a stable RB call set
does not imply stable clone ids.** "Clone 3" at round 3 and "clone 3" at round 4 need
not be the same cells, and every entry in `config/large_clone_comparisons.yaml` is
written in clone ids. Five of the seven paper-retained tumors have a worst-step
Jaccard below 0.5:

| sample | worst Jaccard | clones | RB set varies |
|---|---|---|---|
| `SRX22868103` ★ | 0.150 | 14-18 | no |
| `SRX11133594` ★ | 0.167 | 3-3 | no |
| `SRX11133592` ★ | 0.278 | 4-4 | no |
| `SRX10264523` ★ | 0.400 | 11-13 | **yes** |
| `SRX10831287` ★ | 0.455 | 3-4 | no |

## Caveats

- **Consensus, not clone pairs.** Everything here is computed from
  `segs_consensus_<k>.tsv`. The triage decides eligibility from per-clone genotypes,
  so a change in the consensus call set does not automatically move a triage row.
  The two agree on what a sample *carries*, not necessarily on what a clone *pair*
  acquires.
- **The 0.15 arm-coverage floor is a threshold**, and two of the five varying samples
  sit within 0.04 of it. Their variation is at least as much about the threshold as
  about the round.
- **Breakpoint Jaccard is strict.** It compares exact `CHROM:seg_start` sets, so one
  shifted breakpoint in a small segment set drives the score down hard. Low Jaccard
  means "the segmentation was redrawn", not "the biology changed" — read it beside
  the RB-set column, never alone.
- **Worst step, not mean.** A sample that settles after round 1 and is then stable
  still reports a low score. Use `results/round_variation_by_sample.csv` to see which
  step moved.
- `SRX11133592` and `SRX11133594` have only two rounds, so their Jaccard is a single
  comparison and is not measured on the same footing as the four-round samples.
- No orthogonal SCNA calls exist for these samples, so none of this says which round
  is *right* — only how much the rounds disagree.
